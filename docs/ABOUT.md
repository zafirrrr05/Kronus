# About KRONUS

## Results, measured not asserted

KRONUS is trained and evaluated on real NSL-KDD data. Synthetic data generated by the Digital Twin is used only to support the self-healing training loop; it is not used to produce the reported metrics or run the demonstration.

| Model | Task | Trained on | Evaluated on | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---:|---:|---:|---:|
| Bouncer (XGBoost) | Benign vs. flood, using per-flow rate and entropy features | 125,973 real rows | 22,544 real held-out rows, including unseen attack subtypes | 0.884 | 0.851 | 0.787 | 0.818 |
| Detective (hand-rolled GAT) | Benign vs. port scan, using graph structure | Real rows replayed as labeled graph windows | Real held-out windows | 1.0 | 1.0 | 1.0 | 1.0 |

The Detective's perfect score is specific to a deliberately scoped task. A scanning host has a distinctive fan-out pattern compared with ordinary traffic, making the structural distinction unusually clear. The metric therefore demonstrates structural separability rather than general performance on ambiguous mixed traffic. The gray-zone policy band and seven integration flow cases cover that broader decision boundary.

The Bouncer provides a deliberately simple baseline built from six fast features. Its role is to establish whether the additional complexity of a graph-based detector provides measurable value.

Reproduce the results with:

```bash
python -m services.bouncer.train
python -m services.detective.train
```

See `docs/setup.md` for the complete setup and reproduction steps.

## What's real in this repository

- **Real data.** NSL-KDD is fetched by `scripts/download_data.py`. Because the dataset does not contain IP addresses, they are reconstructed deterministically from the connection-rate features already present in each row. The reconstruction is implemented in `twin/nsl_kdd.py`.
- **Real policy enforcement.** `policy/response.rego` is evaluated by the actual `opa` binary through a subprocess. It is not replaced by a Python implementation of the policy. The required seven policy cases pass, along with additional boundary and defensive cases, for 22 policy tests in total.
- **Real audit trail.** The Logbook uses a hash chain whose entries are verified by recomputing each hash from its stored fields. The test suite deliberately modifies a stored row and verifies that the chain detects the exact point of failure. This has been tested against both SQLite and PostgreSQL.
- **Real SSH service.** The Decoy is implemented as an `asyncssh` server. It has been tested with a real SSH client, including authentication with arbitrary credentials and command execution in a live session.
- **Verified gradients.** The Detective's hand-written Graph Attention Network has been checked against numerical finite differences. The implementation is therefore tested at the gradient level rather than only by observing a decreasing training loss.
- **Verified ONNX inference.** The Detective's inference graph is constructed with `onnx.helper` rather than `torch.onnx.export`. Its output is compared with the NumPy training path within floating-point tolerance, both before and after actual training.
- **159 automated tests.** The repository contains 159 unit and integration tests, all passing. The tests exercise the actual components rather than bypassing the important parts with mocks.

## Key design decisions

The design is intentionally conservative about dependencies, data handling, and failure boundaries.

- **No PyTorch.** The Detective is a sub-200k-parameter, CPU-only model intended to run at laptop scale. Pulling in the 500+ MB PyPI `torch` wheel and its additional dependencies would add substantial weight for little practical benefit. The GAT is implemented in NumPy with `autograd`, and its gradients are checked numerically.
- **Symmetric graph aggregation.** A scanning host can be a pure-source node with high out-degree and no incoming edges. A destination-only directed aggregation scheme would therefore leave that node without messages describing its own behavior. KRONUS aggregates each flow into both endpoints' neighborhoods, which allows the source's structural behavior to contribute to its embedding.
- **Stratified, source-sorted replay.** NSL-KDD rows are not ordered as a temporal stream from individual attackers. Replaying them in their original order weakens the rate signal needed for flood detection and can distort scan traffic. Training streams are therefore sorted by reconstructed source before replay. The resulting feature distributions were checked after retraining.
- **One event-stream abstraction, two backends.** `EventBus` is defined as a shared protocol. The demo and tests use an in-memory implementation, while production uses a Redpanda/Kafka-compatible backend. The Job Queue uses the same primitive as a separate topic instead of introducing another messaging dependency such as Redis.
- **Filesystem model versioning.** Each component keeps model metadata and a `current` pointer. This provides versioning, promotion, and rollback without introducing a separate model-registry service that would add infrastructure without a corresponding benefit at this project's scale.
